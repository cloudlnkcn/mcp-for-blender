## 目标

为 mcp-for-blender 添加 HTTP（Streamable HTTP）与 SSE 传输支持，同时保持 stdio 为默认传输（完全向后兼容）。

## 现状与可行性

- 项目基于官方 `mcp` SDK 1.29.0 的 FastMCP，`server.py:2222` 的 `mcp.run()` 无参调用即 stdio。SDK 原生支持 `transport="streamable-http"` 和 `"sse"`。
- uv.lock 确认 `uvicorn`、`starlette`、`sse-starlette` 均为 mcp 1.29.0 的基础依赖 → **无需新增依赖、无需改锁文件**。
- 现有 `--host`/`--port` 指 Blender socket 地址（非监听地址），HTTP 监听配置必须用独立命名。
- `list_tools` 客户端过滤钩子（server.py:2188）和 `context_log.install`（server.py:2221）基于底层 `mcp._mcp_server`，各传输下均生效，无需改动。addon.py（Blender 插件）完全不需要改动。

## 改动内容

### 1. `src/blender_mcp/server.py` — 核心改动

**新增配置解析**（沿用现有 "CLI > 环境变量 > 默认值" 契约）：
- 新增 `ServerArgs` dataclass 与 `parse_server_args(argv)`：在一次 `parse_known_args` 中解析全部服务端参数（保持对客户端附加未知参数的容忍），`parse_connection_args` 改为薄包装（返回 `(host, port)`），现有测试不受影响
- 新 CLI 参数：`--transport {stdio,http,sse}`、`--http-host`、`--http-port`、`--stateless-http`
- 新环境变量：`BLENDER_MCP_TRANSPORT`、`BLENDER_MCP_HTTP_HOST`（默认 127.0.0.1）、`BLENDER_MCP_HTTP_PORT`（默认 8000）、`BLENDER_MCP_HTTP_STATELESS`（1/true/yes/on）
- `resolve_transport()`：别名归一化（`http`/`streamable-http`/`streamable_http` → streamable-http）；**显式配置了无效传输时报错退出**（静默回退 stdio 会让 HTTP 客户端表现为"挂起"，比崩溃更难排查）
- `resolve_http_listener()`：坏的环境变量端口回退默认值并告警（镜像 `BLENDER_PORT` 现有行为）

**传输启动**：
- 新增 `_run_http_transport()`：设置 `mcp.settings.{host,port,stateless_http}` 后，通过 `mcp.streamable_http_app()`（`/mcp` 端点）或 `mcp.sse_app()`（`/sse` + `/messages/` 端点）构建 Starlette app，用 uvicorn 启动 —— 与 SDK `run_streamable_http_async` 内部做法一致，但让我们能插入中间件
- **可选 Bearer 鉴权**：设置 `BLENDER_MCP_HTTP_TOKEN` 时挂一个简单的 ASGI 中间件校验 `Authorization: Bearer <token>`（HTTP 传输让 `execute_blender_code` 暴露给网络，默认绑定 127.0.0.1 + 可选 token 是最低限度的防护）
- `main()`：stdio 走原路径 `mcp.run()`；http/sse 走新路径；TTY 提示消息按传输区分（现在那条"等待 stdin"提示对 HTTP 模式不适用）

### 2. `src/blender_mcp/addon_manager.py` — 仅帮助文本

`run_cli()` 的 parser 中补声明 `--transport`/`--http-host`/`--http-port`/`--stateless-http`（仿照现有 `--host`/`--port` "仅为 --help 展示" 的模式，见 addon_manager.py:541 注释）。

### 3. `Dockerfile`

加 `EXPOSE 8000` 与注释（镜像运行 `--transport http` 的用法写在 README）。

### 4. `pyproject.toml`

版本 2.1.9 → 2.2.0（不改 uv.lock，与仓库现行做法一致：锁文件中项目版本本就落后于 pyproject）。

### 5. `tests/test_http_transport.py` — 新增测试

沿用 `test_connection_args.py` 的风格：
- 单元：参数解析（新 flags、未知参数仍被容忍）、transport 别名归一化与无效值报错、`resolve_http_listener` 优先级链与坏端口回退、stateless 环境变量解析
- 集成（同步测试内用 `threading` + `asyncio.run`，无新测试依赖）：uvicorn 后台线程分别启动 `streamable_http_app()` 与 `sse_app()`（空闲端口），用 SDK 客户端（`streamablehttp_client` / `sse_client`）完成 initialize + `list_tools`，断言工具列表返回；测试环境设置 `DISABLE_TELEMETRY=1`

### 6. `README.md`

- 新增 "HTTP / SSE Transport" 章节：启动命令、端点 URL（`http://127.0.0.1:8000/mcp`）、Cursor/VS Code/Claude Desktop(mcp-remote)/Codex 的 URL 配置示例、Docker 示例（`docker run -p 8000:8000 … --transport http`）、安全说明（无鉴权风险、默认仅本机、`BLENDER_MCP_HTTP_TOKEN` 用法）
- 更新 Table of Contents 与 Environment Variables 表

## 非目标

- 不改 addon.py / Blender 插件（传输是服务器侧的事）
- 不改 Blender socket 通信层；HTTP 多会话下命令仍由现有 `threading.Lock` 串行化（server.py:115），语义安全
- 不做 OAuth/完整鉴权框架（token 鉴权已覆盖最低需求）
